# 廠商表單網址規範

給行銷與合作對接用。**2026-10-15 全文重寫並與程式碼逐條核對過。**

> ## 先看這裡：正常情況不需要手組網址
>
> **產生連結的正式方式是後台的「UTM 活動」頁（`/admin/campaigns`）**：
> 建一檔活動 → 勾投放管道 → 每個管道各產出一條連結 → 複製去投放。
> 那一頁的「現有合作案表單」表格是**直接讀設定檔即時產生**的，永遠不會過期。
>
> 這份文件是給「要理解參數在做什麼」或「後台產不出來、必須手接參數」時看的。
>
> 🔴 **手寫網址最常見的災難是大小寫。** `utm_campaign` 寫成 `Nanshan` 和
> `nanshan` 會在後台的活動下拉裂成兩個選項，而且**事後救不回來** ——
> `composables/useUtm.ts` 擷取時不做 lowercase 也不比對白名單，
> 而 `leads` 的 PATCH 白名單只放行 `status` 與 `internalNote`，回填不了 payload。

## 一、參數總表

### 站內參數（本站自己定義，不是 GA4 的）

| 參數 | 用在哪 | 作用 | 定義在 |
|---|---|---|---|
| `v` | `/booking`、`/group-booking` | 表單變體：Hero 文案、鎖分店、價格規則、公司歸因 | `config/bookingVariants.ts`、`config/groupClassVariants.ts` |
| `co` | **只有 `/booking`** | 不限年齡免費的合作方（公司名、到期日） | `config/freeTrialPartners.ts` |
| `src` | `/booking`、`/group-booking` | 覆寫名單的「來源」，優先於變體的預設值 | 用下方「來源固定用語」那七個 |
| `tab` | 四個彙整頁 | 選中的分類，瀏覽器上一頁時還原 | 各彙整頁的分類代號 |

`v` 與 `co` 帶了不存在的值都會**無聲退回預設**：不會壞頁、不會報錯，但那批名單的公司與來源會是空的。**打錯一個字母就是這個結果，而且沒有任何告警。**

### UTM 參數（GA4 標準）

| 參數 | 誰決定 | 後台可自由填嗎 |
|---|---|---|
| `utm_source` | 由投放管道自動對應 | ❌ 刻意不開放覆寫 |
| `utm_medium` | 由投放管道自動對應 | ❌ GA4 標準維度 |
| `utm_campaign` | 活動代號 | ✅ 但有格式限制（見下） |
| `utm_content` | 區分同管道的不同素材 | ✅ 選填，一個活動只能填一個 |
| `utm_term` | 後台不產生 | — 但擷取時會一併收下 |

**UTM 存在 cookie `lkk_utm`，30 天、首次擷取、伺服器端讀得到。**
所以讀者從投放連結進站、逛了幾頁再回來填表，歸因仍然保得住。

### 格式限制

```
utm_campaign   ^[a-z0-9][a-z0-9_-]{1,59}$   強制小寫、英數開頭、長度 2–60
v / co / tab   只能英數與底線（會進 Nitro 快取鍵，連字號與中文會被清掉）
```

## 二、管道 → `utm_source` / `utm_medium` 對照

後台勾哪個管道就自動帶這兩個值，**不開放覆寫**。

| 管道 | `utm_source` | `utm_medium` |
|---|---|---|
| 網站 | `website` | `referral` |
| LINE | `line` | `social` |
| Facebook | `facebook` | `social` |
| Instagram | `instagram` | `social` |
| Email | `email` | `email` |
| 傳單 | `flyer` | `offline` |
| Google | `google` | `cpc` |

管道不在表內時的退路是 `website` / `referral`。
來源出處：`utils/campaignLinks.ts` 的 `CHANNEL_TO_SOURCE` 與 `CHANNEL_TO_MEDIUM`。

## 三、來源固定用語（`?src=`）— 請只用這些

`?src=` 存進的是名單的「來源」欄（`leads.payload.leadSource`），與上面的 `utm_source` 是**兩件事**：`src` 給後台的人看，`utm_source` 給 GA4 看。

| `?src=` 值 | 代表 |
|---|---|
| `網站` | 官網／網站連結 |
| `LINE` | LINE 群發／官方帳號訊息 |
| `Facebook` | Facebook 貼文／廣告 |
| `Instagram` | Instagram |
| `Email` | 電子報／EDM |
| `傳單` | 實體 DM／傳單（含 QR code） |
| `Google` | Google 搜尋／廣告 |

**規則：**
1. **品牌名用官方寫法**：`LINE`、`Facebook`、`Instagram`（大小寫照這樣）。
2. **一般管道用上表固定中文字**：官網／網頁／website → 一律 `網站`；電子報 → `Email`。
3. **不要自創同義詞。** 要新增來源類別，先更新這份清單與
   `composables/useAdminLeads.ts` 的 `SOURCE_CHANNELS` 再用。
4. `?src=` 省略時 ＝ 用該變體的預設來源。

## 四、目前可用的變體（`?v=`）

> ⚠️ 這兩張表是**手動維護**的，會過期。
> **即時且永不過期的版本在後台 `/admin/campaigns` 的「現有合作案表單」表格**，
> 那張表直接讀設定檔現算。有疑問以後台為準。
> 以下為 2026-10-15 與設定檔逐條核對的結果。

### `/booking` 客戶預約（`config/bookingVariants.ts`）

| `?v=` | 公司 | 表單特性 | 預設來源 |
|---|---|---|---|
| `abbott` | 亞培 | Hero 換文案。**價格規則與一般人相同**（50 歲以上免費、未滿 50 歲 $500） | LINE |
| `gigabyte` | 技嘉 | Hero 換文案。**價格規則與一般人相同** | 網站 |
| `nanshan` | 南山 | Hero 換文案、**不限年齡免費**、得知管道多一個「南山健康守護圈」 | 網站 |
| `freetrial` | （由 `co` 決定） | **不限年齡免費**、Hero 用內建全齡免費文案、不具名 | 網站 |

**三個都沒有鎖分店，三個都沒有隱藏得知管道。**（舊版文件寫「隱藏得知管道」是錯的。）

### `?co=` 不限年齡免費合作方（`config/freeTrialPartners.ts`）

搭配 `?v=freetrial` 使用。`co` 帶的是**代號**不是公司名，查不到就當沒帶。

| `?co=` | 公司 | 有效期間 |
|---|---|---|
| `taiwanlife` | 台灣人壽 | 至 2027-10-31（民國 116/10/31）止 |

到期後連結會**自動退回一般表單**（會顯示「未滿 50 歲 $500」），不需要再部署。
🔴 **到期前要主動通知對方停止投放**，否則被承諾免費的人會看到要收費。

### `/group-booking` 團體課報名（`config/groupClassVariants.ts`）

**目前沒有任何合作案變體**，只有 `default`。
亞培與南山的團課變體已於 2026-09-11 依業主指示刪除；
舊連結 `/group-booking?v=abbott`、`?v=nanshan` 不會壞頁，會自動退回一般團課表單
（但名單不再帶公司與來源）。

團課變體另支援 `lockStore`（鎖定門店，填「南京店」即可）與 `lockCourse`（鎖定課程），
設定後該欄位改成唯讀卡片、不再讓填單人選。

> 加新公司＝在對應的變體設定檔加一段設定（不用改主程式），push 後幾分鐘自動部署。

## 五、網址組裝

後台產生的連結固定是這個順序（方便目視比對）：

```
{網域}{路徑}?v=…&utm_source=…&utm_medium=…&utm_campaign=…&utm_content=…
```

⚠️ **`co` 與 `src` 後台不會幫你加**，需要時自己接在後面。

### 範例

```
# 一般合作案（後台產得出來）
亞培 · LINE
https://lkkwellness.com/booking?v=abbott&utm_source=line&utm_medium=social&utm_campaign=abbott

技嘉 · 網站
https://lkkwellness.com/booking?v=gigabyte&utm_source=website&utm_medium=referral&utm_campaign=gigabyte-50plus-free-trial

南山 · Email
https://lkkwellness.com/booking?v=nanshan&utm_source=email&utm_medium=email&utm_campaign=nanshan-2026

# 不限年齡免費合作方（要自己接 co，後台產不出來）
台灣人壽 · LINE
https://lkkwellness.com/booking?v=freetrial&co=taiwanlife&utm_source=line&utm_medium=social&utm_campaign=taiwanlife-2026

# 覆寫名單來源（同一變體、不同管道）
https://lkkwellness.com/booking?v=nanshan&src=傳單
```

> 需要縮短網址時用外部工具（reurl.cc / bit.ly）即可，所有參數都會保留。

## 六、參數最後進到名單的哪個欄位

```
v        → payload.formVariant
co       → payload.company      （經名冊查表；查不到就不帶）
變體設定  → payload.company      （v 自己帶的 company）
src      → payload.leadSource    （優先於變體的預設來源）
utm_*    → payload.utm.{source, medium, campaign, content, term, landingPage}
```

後台「客戶預約」頁可用**公司／來源／UTM 來源／UTM 活動**四個維度篩選，
CSV 匯出含「表單變體」欄。

## 八、維護這份文件時

這份文件裡**會過期的只有第四節**（變體清單）。其餘各節的事實來源：

| 內容 | 真正的來源 |
|---|---|

| `utm_campaign` 格式 | `utils/campaignLinks.ts` 的 `CAMPAIGN_CODE_RE` |
| `?src=` 七個用語 | `composables/useAdminLeads.ts` 的 `SOURCE_CHANNELS` |

| `co` 合作方 | `config/freeTrialPartners.ts` |
| 團課變體 | `config/groupClassVariants.ts` |
| UTM 擷取與保存 | `composables/useUtm.ts` |

改了上面任何一個檔案，請回來更新對應的段落。
